# 微信小程序提问者端

小程序与网页共用 Django、SQLite 和同一份问题数据。小程序提供投递、公开回信、我的提问及详情；主人仍在网页 `/owner/` 回答、发布、编辑和删除。

仓库默认开启本机演示，API 示例为 `https://ask.example.com/api/v1`；真实模式连接部署者自己的后端，打开即进入公开回信首页。页面沿用网站的 QUESTIONBOX 品牌、黄底便签、彩色回信卡片和明暗／跟随系统主题按钮；提供同样的精选回答、所有回答及单标签筛选。精选忽略标签，所有回答按标签过滤；筛选和公开统计共用网站后端函数。小程序不提供主人登录入口。

公开回信与网页移动端保持相同分页规则：每页 7 条，底部最多显示 5 个连续页码，当前页高亮。点击页码替换列表并滚动到列表标题，翻页保留精选／所有回答和标签；切换筛选回到第 1 页。从详情返回或下拉刷新时保留当前页，回答删除导致页码越界时退回最后一页。翻页失败保留当前回信，点击“重新加载”重试目标页；快速切换以最后一次请求为准。“我的提问”继续每页 10 条、触底或点击按钮追加加载。

“公开回信”页提供“沉浸式阅读”入口，保留原有列表。原生叠层卡片支持左滑下一封、右滑上一封；返回时上一封从左侧跟手滑入，当前卡片退入叠层，短滑或中断手势会回弹。每封回信的颜色在切换、返回和洗牌后保持一致，支持明暗主题和卡片内长回答滚动。阅读沿用公开分页接口，无需微信登录，演示模式也可使用。

右上角菜单支持原生分享：公开首页、公开回答详情和沉浸式阅读可转发给朋友或分享到朋友圈；公开回答只携带公开问题 ID，接收者无需登录即可阅读。阅读器分享的是“随便读读”入口，不固定到当前随机回信。从分享直达阅读器时，“返回公开回信”会在无上一页的情况下打开首页。私人问题详情、我的提问和提问表单只转发公开首页，并禁用朋友圈入口。默认分享使用固定本地封面，避免微信默认截图带出私人内容、草稿或邮箱；公开回答详情会在加载后用本机画布提前生成问题原文封面，自动换行、长文省略，好友和朋友圈使用同一张图片。图片生成失败、尚未就绪或问题变化时回退通用封面，私人问题不生成图片。

详情页顶部和底部均提供“返回首页”，使用 `switchTab` 进入公开回信；底部“返回首页”和“再投一张便签”采用圆角胶囊按钮。朋友圈单页模式（场景 1154）按微信限制隐藏无法使用的跳转按钮和分享菜单操作，保留完整回答与微信自带“前往小程序”的说明。三个主页面使用带回信、书写和个人图标的自定义浮动圆角底栏，衬线字、选中配色和明暗主题与便签界面一致；输入键盘弹出时收起底栏，页面底部留出安全区域，主题与当前页面高亮自动同步。

## 无账号演示

1. 在微信开发者工具中导入项目根目录下的 `miniprogram/`；项目使用占位 `touristappid`，选择工具支持的游客模式查看演示。真实模式需替换为自己的 AppID。
2. `config.js` 默认 `demo: true`，即可查看便签风格界面、明暗主题、公开回信、私人记录、模拟投递与模拟提醒；联调和上传前改回 `false`。
3. 演示数据只写入本机 `qb-demo-v1` 存储，不访问服务器、不调用微信登录和消息授权、不发送邮件。界面会明确显示演示提示。清除开发者工具存储可恢复示例。

演示不会证明真实微信登录、网络域名或订阅模板可用。演示记录不会在切换真实模式后上传。

## 接入真实账号

注册后在微信开发者工具填入实际 AppID。服务端配置：

```dotenv
WECHAT_ENABLED=1
WECHAT_APPID=你的实际AppID
WECHAT_APP_SECRET=你的实际AppSecret
WECHAT_SESSION_DAYS=30
WECHAT_REPLY_TEMPLATE_ID=已申请的回复提醒模板ID
WECHAT_REPLY_TEMPLATE_FIELDS={"thing1":"notice","time2":"time"}
WECHAT_MINIPROGRAM_STATE=trial
```

字段映射必须按**实际已批准的模板**填写，以上 `thing1`、`time2` 只是示例，不保证你的模板使用这些字段。支持 `thingN:notice`（你有一封新回信）、`thingN/phraseN:status`（已回复）、`timeN:time`（首次回复时间）、`dateN:date`。没有模板或映射时，微信登录和投递可以启用，但回复提醒入口关闭。

`WECHAT_MINIPROGRAM_STATE` 选择 `developer`、`trial` 或 `formal`，与开发版、体验版或正式版对应。AppSecret 只保存在服务端 `.env`；前端只需要 AppID、API 源站和可公开的模板 ID。

修改 `miniprogram/config.js`：

```js
module.exports = {
  demo: false,
  apiBase: 'https://ask.example.com/api/v1'
};
```

在微信公众平台的小程序“开发管理 → 开发设置 → 服务器域名”中，将 request 合法域名设置为自己的 HTTPS 源站，例如 `https://ask.example.com`（不带 `/api/v1`）。保留开发者工具的域名校验，并按账号平台实际要求配置服务器与隐私声明。

服务端 `WECHAT_APPID` 必须与 `project.config.json` 的实际 AppID 一致。AppSecret 只填写到服务器私有 `.env`；重建 web 和 worker 容器后生效。缺少 AppSecret 时公开阅读仍可用，真实投递和“我的提问”不可用。AppSecret、Bark Key 和其他服务凭据禁止进入前端或 Git 仓库。

## 接口约定

所有路径以 `/api/v1` 开头，保留末尾 `/`；POST 使用 `application/json`，最大 16 KiB。需要身份的请求带 `Authorization: Bearer <token>`。网页登录 Cookie 不提供 API 权限。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /meta/` | 返回站点标题、主人名字、700 字及容量限制、箱满状态、微信／邮箱／提醒能力，以及启用后的模板 ID |
| `POST /wechat/session/` | 接收 `{"code":"wx.login返回的凭证"}`，返回随机 `token` 和 ISO 8601 `expires_at` |
| `GET /questions/?page=1&view=featured&per_page=7` | 公开问答，与网页共用精选／所有回答规则；支持 `view=all&tag=标签ID`；默认不带 `view` 保持所有回答，默认每页 5 条，可选 7/14；小程序问答墙使用 7 |
| `POST /questions/` | 需要身份；接收 `text`、可选 `signature`、可选 `email`、必填 UUID `client_request_id` |
| `GET /questions/{id}/` | 已发布问答详情，未发布或删除返回 404 |
| `GET /me/questions/?page=1` | 需要身份；本人提问，提交时间倒序，每页 10 条 |
| `GET /me/questions/{id}/` | 需要身份；本人问题和已发布回复，允许本人查看待回复问题 |
| `POST /me/questions/{id}/wechat-reminder/` | 需要身份；接收 `{"enabled":true/false}`，客户端只能在实际订阅授权成功后开启 |

列表返回 `items`、`page`、`has_more` 和 `count`。详情及投递返回 `question`；首次创建为 HTTP 201 与 `created:true`，重复提交为 HTTP 200 与 `created:false`。

问题响应包含 ID、原文、可选署名、显示名字、提交时间、已发布回复、首次回复时间、更新时间、版本、`pending/answered` 状态、`is_featured` 和 `tags:[{id,name}]`。待回复问题不暴露标签和精选标记。公开列表还返回 `selected_view`、`selected_tag`、仅关联公开回答的 `tags`、`public_answer_count` 和 `public_topic_count`。私人响应额外包含 `wechat_reminder.enabled/status`。不返回草稿、邮箱、微信标识、会话摘要或提交摘要。

错误结构：

```json
{"error":{"code":"rate_limited","message":"请等待 30 秒再试。","retry_after":30}}
```

字段错误额外返回 `fields`。401 表示重新微信登录；404 表示不存在或无权访问；409 表示箱满或提交标识内容冲突；413/415 表示请求大小／格式有误；429 附带 `Retry-After`；503 表示能力关闭或微信服务暂不可用。

### 身份、幂等与同步

- 按 AppID 与 OpenID 识别同一用户；会话使用随机令牌，仅保存 SHA-256 摘要，默认 30 天。更换设备登录同一微信账号仍归属于同一身份。
- 网页和历史问题的微信归属为空，不自动认领。不提供回答、草稿或删除问题的 API。
- 投递标识按用户隔离，数据库事务同时检查重复投递和 500 条容量。相同标识与相同规范化内容返回原问题；内容变化返回冲突。摘要包含规范化邮箱，不重复保存邮箱明文。
- 幂等记录与问题一起保存，删除问题后该标识不再保留。不要把已删除问题的旧请求当作新的投递重试。
- 小程序按输入内容生成并保存投递标识，网络失败后保留输入与标识；输入变化后新投递使用新标识。收到成功结果才清除本机草稿。
- 发布与更新直接作用于同一份问题记录，小程序在页面重新进入或下拉刷新时读取最新回复。保存草稿不改变公众看到的回复。
- 微信个人频率额度沿用每分钟 1 条、每小时 10 条；IP 与全站额度和网页共用。微信登录另有每 IP 每 15 分钟 30 次限制。

`WECHAT_ENABLED=0` 关闭微信登录及私人 API，公开只读接口仍可使用。更换 AppID 后旧 AppID 的令牌无法访问新账号；更换 `SECRET_KEY` 时建议清除微信会话并让客户端重新登录，以免投递摘要更换后无法核对旧请求。

## 微信提醒、邮件与运维

**Bark 是给主人的新提问提醒**，与提问者的微信订阅消息相互独立。网页和小程序都通过 `submit_question` 在同一事务里创建问题及 Bark 任务；相同投递标识的重试不重复创建任务。只需保留服务端 `BARK_DEVICE_KEY` 和运行中的 worker，即可处理小程序新提问，无需在小程序添加主人登录。通知只含通用提醒和网站的主人问题详情链接，点击后在网站登录查看。不要把 Bark 密钥下发给客户端。

提交成功后由用户主动点击“回复时提醒我”，立即调用微信授权，再保存该问题的提醒状态。拒绝不影响问题。首次发布创建一次任务；在已经发布后授权也可以补建一次任务；后续编辑不新增微信提醒。邮件按现有行为发送首次回复及更新，两种通道可以并存。

任务由现有 `mail_worker` 发送。唯一任务记录保留到问题删除，作为不重复发送的凭证。微信通知只包含通用提示、首次回复时间和私人详情入口，不包含原文、署名、邮箱或答案。

任务状态：

| 状态 | 含义 |
| --- | --- |
| `pending/sending` | 等待发送／正在发送 |
| `sent` | 微信明确接收了发送请求 |
| `failed` | 可重试错误超过 5 次，需要修复配置后重排 |
| `rejected` | 微信明确拒绝，例如无订阅权限，不自动重试 |
| `uncertain` | 发送超时、响应无法确认或发送进程中断，可能已经送达，不自动重发 |
| `cancelled` | 问题删除或用户停止等情况下取消 |

主人收件箱显示失败和结果不明确的数量，并提供重排明确失败任务的按钮。命令行：

```sh
.venv/bin/python manage.py retry_failed_wechat
.venv/bin/python manage.py retry_failed_wechat --job 123
# 先核对单个任务。此命令可能重复发送已经送达的消息。
.venv/bin/python manage.py retry_failed_wechat --job 123 --include-uncertain
```

无订阅权限的任务不进入自动重排。停止通知可取消未发送任务，正在发送或已送达的消息可能无法撤回。更换到新微信账号时，旧账号的待发任务会取消。外部接口错误只保存固定原因或数字代码，不保存 provider 原始响应或包含密钥的 URL。

过期会话由 worker 清理；微信身份保留用于跨设备归属。数据库备份现在也包含微信标识和私人关联，应继续保持私有。

## 迁移、验证和发布

新增迁移只增加表、可空归属字段及幂等字段，历史内容不重新绑定。先备份再迁移：

```sh
.venv/bin/python manage.py backup_database
.venv/bin/python manage.py migrate
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test box --noinput
node --test miniprogram/tests/*.test.js
```

本地测试用隔离数据库和模拟微信服务，不使用真实违法内容，不发送真实邮件或通知。原有网页、邮件、Server 酱测试继续覆盖兼容性。

后端使用通用 Docker Compose 部署，启动前备份数据并执行迁移。小程序在 `.dockerignore` 中排除，不放进 Django 镜像。通过微信开发者工具上传小程序源码，上传包排除测试目录；部署后端不会自动发布微信小程序。

真实体验版验收至少包括：合法域名校验开启后请求成功、同账号跨设备记录一致、不同账号私人数据隔离、投递／草稿／发布／编辑／删除同步、首次回复提醒及拒绝授权、可选邮件和会话过期重登。通过账号资质、隐私与内容审核要求核验后，才进入正式发布阶段。
